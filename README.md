# PDF Downloader

ปลั๊กอิน component สำหรับ **Budibase 3.4.1** พัฒนาด้วย **Svelte 3.59.2** เท่านั้น (ไม่มี React, Vue หรือ Svelte 4/5) ปุ่มใน Design แสดง **PDF Download**

ไฟล์พร้อมติดตั้ง: [pdf-downloader-1.0.2.tar.gz](releases/pdf-downloader-1.0.2.tar.gz) — บน GitHub กด Download raw file เพื่อดาวน์โหลด

## ติดตั้งใน Budibase

1. ใช้ไฟล์ `dist/pdf-downloader-1.0.2.tar.gz` ที่สร้างด้วย `npm run build` ห้ามเปลี่ยนเป็น ZIP
2. ใน Budibase เปิดส่วน Plugins ของ workspace แล้วนำเข้าไฟล์ tar.gz (บัญชีและรุ่นที่ใช้งานต้องเปิดใช้ custom plugins)
3. เปิดแอปใน Design แล้วเพิ่ม component **PDF Downloader**
4. ลาก components ของเอกสารเข้าไปเป็น children ของ PDF Downloader เช่น Container, Text, Image และตารางที่ render ข้อมูลครบแล้ว
5. ตั้งค่าผ่านแผง component แล้วทดสอบดาวน์โหลดใน Preview หรือแอปที่เผยแพร่

หากต้องการปุ่มแยกจากเอกสาร ให้กรอก **CSS selector ของเอกสาร** เช่น `#report` หรือ `.report-document` โดย element นั้นต้องมี ID/class จริงใน DOM และ selector ต้องตรงเพียงหนึ่งรายการ หากเว้นว่างจะส่งออก children ภายใน component ปุ่มและข้อความสถานะจะไม่ติดไปใน PDF

| ความละเอียด | 1–3; ค่าเริ่มต้น 2; ลดเหลือ 1 สำหรับเอกสารยาว |

| ข้อความท้ายขวา | ค่าเริ่มต้น `รหัสเอกสาร` |

## การจัดหน้าและข้อจำกัด

- เก็บรูปแบบ DOM ที่ render แล้ว รวมถึง grid, flex, สี, รูปภาพ และแบบอักษรจากหน้าจอ ปรับสัดส่วนให้พอดีความกว้างกระดาษโดยไม่ยืดภาพผิดสัดส่วน และแบ่งตามความสูงที่เหลือหลังกันพื้นที่ footer
- พยายามไม่ตัดกลางแถวตาราง ย่อหน้า หัวข้อ หรือรูปภาพที่มีความสูงไม่เกินหนึ่งหน้า สำหรับ block ใหญ่เกินหน้าจำเป็นต้องแบ่งภาพ ใช้ `data-pdf-keep` เพื่อระบุ block ที่ต้องการเก็บด้วยกัน และ `data-pdf-break-before` เพื่อขึ้นหน้าใหม่ได้เมื่อควบคุม HTML ได้
- ขยาย scroll containers ในสำเนาเอกสาร ไม่แก้หน้าจอจริง ไม่โหลดข้อมูลเพิ่มจากฐานข้อมูล ดังนั้น virtualized grids, pagination, collapsed tabs และเนื้อหาที่ยังไม่โหลดจะไม่ถูกส่งออกทั้งหมด ต้องเตรียมมุมมองเอกสารที่ render ครบก่อน
- layout กว้างมากจะย่อจนตัวอักษรเล็ก ควรใช้แนวนอนหรือจัดมุมมองเอกสารเฉพาะ ไม่มีตัวจับภาพ DOM ที่รับประกันทุก CSS, iframe, video, WebGL หรือ third-party widget ได้เหมือนหน้าจอทั้งหมด
- PDF เป็นภาพแต่ละหน้า เพื่อคงภาษาไทยและรูปแบบให้ตรงหน้าจอ **ข้อความใน PDF จึงไม่ใช่ข้อความที่เลือก ค้นหา หรืออ่านด้วย screen reader ได้** ลิงก์และ input ไม่เป็น interactive PDF
- รอโหลดฟอนต์และรูปภาพก่อนส่งออก ฟอนต์ไทยต้องมีอยู่ในหน้าจอ/เบราว์เซอร์ รูปภาพข้ามโดเมนต้องอนุญาต CORS; CSS background images ที่ไม่มี CORS อาจไม่ปรากฏ หลีกเลี่ยงทรัพยากรภายนอกที่จำกัดสิทธิ์
- เพื่อจำกัดหน่วยความจำ รองรับ canvas ไม่เกิน 16,000 px ต่อด้าน, 32 ล้านพิกเซล และ 100 หน้า เกินขีดจำกัดจะแสดงข้อผิดพลาดให้ลดความละเอียดหรือแบ่งชุดข้อมูล
- ประมวลผลเอกสารใน browser ไม่มีการส่งเนื้อหา PDF ไปยังบริการภายนอก ยกเว้นการโหลดทรัพยากรรูปภาพตาม URL ที่กำหนด

## พัฒนาและทดสอบ

ใช้ Node.js 22+ และ npm; ใน cloud นี้ทดสอบด้วย Node.js 24

```sh
npm ci
npm run build
npm test
npm run dev
```

หน้า demo ใช้ `demo/App.svelte` และ Svelte 3 แสดงเอกสารไทยสองคอลัมน์และตารางหลายหน้า เมื่อแก้ source ให้รัน `npm run build:demo` ใหม่หรือ restart `npm run dev` (ไม่ได้เปิด Svelte HMR) ไฟล์ bundle demo ไม่ถูกใส่ในปลั๊กอิน

```sh
npx playwright install chromium
npm run build
npm run test:browser
```

กรณีมี Chromium อยู่แล้ว กำหนด `CHROMIUM_PATH` ให้ Playwright ได้ เช่น `CHROMIUM_PATH=/path/to/chromium npm run test:browser` ใช้ `CHROMIUM_NO_SANDBOX=1` เฉพาะ browser ทดสอบใน container ที่จำเป็น

## ความเข้ากันได้และการตรวจสอบ

ตรวจ integration contract จาก source tag `3.4.1` ของ Budibase (`251974d0b3b25ce630c80c54e6c7dab755d72037`):

- IIFE ลงทะเบียนผ่าน `##BUDIBASE_CUSTOM_COMPONENTS##` / `registerCustomComponent`
- ใช้ globals `svelte` และ `svelte_internal` ตาม client รุ่น 3.4.1; bundle store helper ที่ host ไม่ได้ expose ไว้ภายใน
- ใช้ context `sdk.styleable` และ `component.styles` พร้อม `<slot>` สำหรับ children
- แพ็กเกจประกอบด้วย `plugin.min.js`, `schema.json` (SHA-1 สำหรับระบบ Budibase) และ `package.json`

ชุดทดสอบ browser ตรวจดาวน์โหลดจริงและอ่านไฟล์ PDF รวมถึงโหลด production IIFE ใน host จำลอง Svelte 3 การทดสอบนี้ไม่ได้แทนการนำเข้าใน Budibase server 3.4.1 จริง ควรตรวจรับกับแอปจริง โดยเฉพาะข้อมูล binding, theme, font และตารางเฉพาะของแอป

## อัปเดตจาก 1.0.0 เป็น 1.0.1

แก้ปุ่มไม่แสดง: Budibase 3.4.1 สร้าง component ID จาก `package.name` แต่ client ลงทะเบียนจาก `schema.schema.name` ใน 1.0.0 ชื่อสองตำแหน่งไม่ตรงกัน รุ่น 1.0.1 ใช้ `pdf-downloader` เหมือนกันและคง `friendlyName` เป็น PDF Downloader

อัปโหลดไฟล์ 1.0.1 ผ่าน Plugins เพื่ออัปเดตปลั๊กอินเดิม แล้วรีเฟรชหน้า Design แบบล้าง cache (`Ctrl+Shift+R`) component เดิมที่อ้างอิง `plugin/pdf-downloader` ใช้งานต่อได้ ไม่ต้องลบ container หรือข้อมูลเอกสาร

หากวางปุ่มเป็น sibling ของ Container เอกสาร ให้ระบุ CSS selector ของ container เช่น `[data-id="รหัส-component-จริง"]` จาก DOM ในหน้าจอ Preview; ชื่อในต้นไม้ เช่น `Container 30` ไม่ใช่ CSS selector หรือย้าย container มาเป็น child ของปลั๊กอินและเว้น selector ว่าง ทดสอบดาวน์โหลดใน Preview

การทดสอบ regression จำลองการ resolve component ตาม ID ของ Budibase server แทนการหยิบ component ตัวแรกจาก registry ซึ่งทดสอบเดิมไม่ครอบคลุม

## 1.0.2: รวมส่วนลงชื่อให้พอดีหน้ากระดาษ

เลือก **การจัดหน้า PDF → พอดีหนึ่งหน้า — รวมส่วนลงชื่อ** สำหรับแบบฟอร์มที่ต้องอยู่หน้าเดียว ระบบคำนวณจากทั้งความกว้างและความสูง โดยกันขอบและพื้นที่ footer ก่อน ย่อเท่ากันทั้งสองแกนและจัดกึ่งกลางแนวนอน ไม่ตัดส่วนลงชื่อทิ้ง Footer และลายน้ำยังอยู่ตามตำแหน่งกระดาษ

ค่าเริ่มต้น **อัตโนมัติ** จะรวมเอกสารที่เกินหน้าเพียงเล็กน้อยโดยย่อไม่เกิน 20% เอกสารยาวยังแบ่งหลายหน้าตามเดิม; การบังคับขึ้นหน้าใหม่ด้วย `data-pdf-break-before` ยังคงทำงานในโหมดอัตโนมัติ/หลายหน้า ส่วนโหมดพอดีหนึ่งหน้าจะรวมทุกส่วน แม้มีคำสั่งขึ้นหน้าใหม่ เอกสารยาวมากในโหมดนี้อาจอ่านยาก จึงควรใช้หลายหน้า
